# 表示名の取り方と絵文字の扱い

- 確認日: 2026-11-17
- 方法: 旧クライアントは Claude in Chrome（ログイン済み）、新クライアントはログアウト版の SSR を curl またはログイン済みのタブから `fetch(path, {credentials: 'omit'})` で取得

## 取り方

| クライアント | 画面 | 取り方 |
|---|---|---|
| 旧 | タイムライン、ツイート詳細 | `article` 内の `[data-testid=User-Name]` の最初の `span` |
| 旧 | メディアタブ | `main` 内の `[data-testid=UserName]` の最初の `span` |
| 旧 | ライトボックス | `body` 内の `a[href="/<user>"]` のうち、テキストが `@<user>` で始まらないもの |
| 新 | ツイート詳細、プロフィール | `article` 内の `a[href="/<user>"]` のうち、テキストを持ち `@` で始まらないもの |

`a[href="/<user>"]` を使う方法は、旧・新のどちらでも使えます。新クライアントでは `data-testid` がないので、この方法しか使えません。

新クライアントの `article` 内の `a[href="/<user>"]` は 3 つあります。

1. アイコン（`<img alt="@<user>">`、テキストなし）
2. 表示名（`<div dir="auto">表示名</div>`）
3. `@<user>`

表示名のリンクは、`@<user>` のリンクのすぐ前にあります（2026-11-17、`/NASA/status/2119846862286930036` の SSR で `""`、`"NASA"`、`"@NASA"` の順）。

## 表示名のリンクがない画面（2026-11-17 確認）

Claude in Chrome（ログイン済み、旧クライアント）で `@NASA` を調べました。

- **メディアタブ `/<user>/media?filter=photo`**: 表示名を持つ `a[href="/NASA"]` はありません。ページ全体で一致するのは、テキストが「ポスト」のリンク 1 つだけです。`@` で始まらないテキストを表示名とみなすと、これを拾ってしまいます。
- **メディアタブから開いたライトボックス**: 同じく、表示名を持つリンクはありません。
- **タイムラインから開いたライトボックス**: 背後のタイムラインの `article` が DOM に残っているので、そこから取れます。

## 引用ツイートの表示名（2026-11-17 確認）

- **旧クライアント**: 引用元のユーザーの `a[href="/<引用元>"]` は、`article` の中にありません（引用元 `@Gashapon_Bandai` で確認）。`article` 内の最初の `[data-testid=User-Name]` は、外側（引用した側）のツイートのものです。引用元の画像に対して `article` の最初の User-Name を取ると、引用した人の名前になります。
- **新クライアント**: 引用元のツイートは、入れ子の `<article>` です。その中に引用元の `a[href="/<引用元>"]` が 3 つ（アイコン、表示名、`@<引用元>`）あります（SSR で確認）。

## document.title

| クライアント | 画面 | title の例 | `@<user>` を含むか |
|---|---|---|---|
| 旧 | プロフィール、メディアタブ | `NASA（@NASA）さん / X`、`NASA（@NASA）さんの画像 / X` | 含む |
| 旧 | ライトボックス | 開く前の画面の title のまま（メディアタブから開くと `NASA（@NASA）さんの画像 / X`） | 画面による |
| 旧 | 検索、ホーム | `filter:… - 検索 / X`、`ホーム / X` | 含まない |
| 新 | プロフィール | `NASA（@NASA） / X` | 含む |
| 新 | ツイート詳細 | `XユーザーのNASAさん: 「本文…」 / X` | **含まない** |

確認はすべて日本語の UI で行いました。英語の UI での形式は未確認です。未読の通知があるとき、先頭に `(3) ` のような件数が付くかどうかも未確認です。

## 絵文字の扱い

表示名に絵文字があるとき、取れるテキストがクライアントによって違います。

- **旧クライアント**: 絵文字は `<img>` で描画されるので、`span` のテキストからは消えます。
- **新クライアント**: 絵文字はテキストのまま `<div dir="auto">` に入っています。
- **syndication API**: `user.name` に絵文字が残ります。

例: `彩恵りり🍀科学ライター兼Vtuber (お仕事募集中)`（@Science_Release）

- 旧クライアントの DOM: `彩恵りり科学ライター兼Vtuber (お仕事募集中)`
- 新クライアントの DOM と syndication API: `彩恵りり🍀科学ライター兼Vtuber (お仕事募集中)`

同じアカウントでも、旧クライアントと新クライアントで `textContent` の結果が変わります。

2026-11-17 に、絵文字を含む表示名の 4 アカウントで比べたところ、新クライアントのテキストから絵文字を除くと、旧クライアントのテキストと一致しました。

### 絵文字の判定に使う Unicode の性質

- `\p{Extended_Pictographic}` には、♡（U+2661）、♪（U+266A）、★（U+2605）のような記号も含まれます。名前によく使われる文字なので、絵文字だけを消すつもりでこれを使うと、記号まで消えます。
- `\p{Emoji}` は ♡ ♪ ★ ☆ を含みません。ただし ASCII の数字、`#`、`*`、©、®、™ を含みます。
- 旧クライアントで ♡ ♪ ★ や ©®™ が `<img>` になるか、テキストのまま残るかは未確認です。
